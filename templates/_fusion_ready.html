會一起帶入哪些設定,為什麼
· 遮罩也用在抽特徵 —— 物件在兩輪之間被搬動過, 房間跟物件不是剛體關係,背景特徵只會給出錯誤的約束。這是融合能成立的關鍵。
· 輸出的照片也去背 —— 去畸變後拿遮罩把 images/ 的背景塗黑, 並在旁邊留一份對齊好的 masks/。單一物件重建下游只想看到物件。
· 影像解析度 = 保持原樣 —— 遮罩是在現在這個尺寸上做的,COLMAP 再縮一次就對不上 (會直接報錯,不會默默算錯)。
· MATCHER = vocab —— 快,先試這個。要留意同一組內的相似度比跨組高一個數量級, 檢索名額可能被同組鄰居吃掉,那少數幾對「把兩半縫起來」的配對就不會被嘗試;真的裂成兩塊時, 先把 NUM_MATCHES 調大(預設 50),不夠再換 exhaustive (每一對都比、保證試過,但 1000 張 ≈ 50 萬對)。
· CAMERA_MODE = {{ 'single' if single_camera else 'per_folder' }} —— {{ '各組尺寸一致,同一顆鏡頭就該共用一組內參。' if single_camera else '各組尺寸不同,所以每組各自一組內參。' }}
· rig 關閉 —— rig 的前提是「同一次曝光被所有相機覆蓋」,兩輪先後拍的必然不成立。
跑完怎麼看有沒有真的融合成功
看 log 裡的 sparse/0 coverage: 那一行 —— 每組都大部分註冊,才是真的合成一個模型;某一組趨近 0 就是沒縫起來 (它上面的 mapper produced N models 會一起說明裂成幾塊)。
再到 🧊 3D 結果 看一眼:應該是一個完整物件、底面補起來了, 而且表面紋飾沒有錯位重疊 —— 有雙重紋飾的話是兩輪用錯的旋轉對上了。
真的沒縫起來,最有效的補救是補拍:把物件側倒到中間角度繞一圈拍 15~30 張當橋樑, 比任何事後對齊都可靠。

Inputs

縮成實體檔跑整條 COLMAP(存到 workspace/images_<長邊>)。預設 1920(傾斜攝影甜蜜點);要高解析訓練圖選 4096(再大 3DGS 吃不消)。7680（8K）= 接近原圖(11664)又先轉成乾淨 JPG,避開髒航測 TIFF 在 undistort 崩的坑。「保持原樣」= 用原始檔。

⬚ 只重跑框選範圍
選片用 blocksplit 那套已驗證的兩階段規則:相機中心在框內 OR 可見度 V_ij/V_i ≥ vis_thresh — 所以框外但拍進框內的傾斜鏡頭會一起帶上, 不會只留飛過頭頂的那幾張。外擴只放大餵給可見度測試的點遮罩(與 blocksplit 一致, 相機中心那一關永遠用原始框)。整條流程(抽特徵→比對→mapper→align→去畸變) 都只跑選中的影像;align 會把新模型釘回同一個參考框架,可直接與舊結果疊比。 清空 region 就回到跑整個資料集。
輸入格式（手動指定 layout / subfolders）
兩格都留預設(自動偵測)即可,偵測錯了才手動指定。
影像資料夾的結構,決定「哪些影像算同一台相機」:
‧ single = XXX/*.jpg,全部同一台相機
‧ multi = ROOT/<group>/*.jpg,每個子資料夾一台相機 —— 多鏡頭傾斜 rig 用這個
‧ nested = ROOT/<group>/<video>/*.jpg,影片轉幀
搭配 Camera 組的 CAMERA_MODE=per_folder,每個 group 會共用一組內參。
逗號或換行分隔,留空 = 自動偵測(例如 A, B)。 只在 multi / nested layout 下有意義:用來指定只跑其中幾個子資料夾,或在自動偵測抓錯時手動指定。
多相機 rig（傾斜攝影 / 多鏡頭同步曝光）
多鏡頭同時曝光的機組才需要開。開了之後 COLMAP 會知道「這幾張是同一次曝光」, 用剛性約束綁住鏡頭之間的相對位置 —— 大幅減少大場景的姿態漂移。單相機請留關。
開啟後會多兩個階段:先把影像重新整理成 <相機>/<曝光編號> 的符號連結樹(原始檔不動),抽完特徵再跑 rig_configurator 把 rig/frames 寫進資料庫。分組結果會印在 log, 沒有任何一個曝光被所有相機覆蓋時會直接中止(那種 rig 等於沒有約束力)。
跟 MAPPER 的關係 —— 自動處理,不用你設定:產生的 rig 設定不帶鏡頭外參。 global 能自己把未知外參標定出來,所以是單遍重建。 pose_prior / incremental / hierarchical 要求外參必須已知,會自動改走兩遍:先不帶 rig 重建一次 → rig_configurator --input_path 從那個重建平均出外參寫回資料庫 → 再用你選的 mapper 正式重建。代價是重建時間約兩倍。
怎麼判斷「哪幾張是同一次曝光」。維持 auto 就好:
‧ auto(預設,建議) — 相機 = 第一層資料夾,曝光編號自動從檔名找出來。 作法是把檔名裡的每個數字欄位都試一遍,選「能讓最多次曝光被所有相機同時涵蓋」的那個。 像 B-1_0-70924.jpg / N-1_0-61214.jpg(機身流水號不同)這種它會自己認出 1_0 是共用鍵。不用填下面任何一格。
‧ folder — 曝光 = 資料夾後面的整個檔名。各鏡頭檔名本來就完全一致時才用。
‧ regex — auto 猜錯時的手動指定(見下欄)。
‧ gps — 用 EXIF GPS 位置分群。檔名毫無規律可循時的退路。
不管哪種模式,分組結果都會印在 log,沒有任何曝光被所有相機覆蓋時會直接中止。
auto / folder / gps 模式請留空。 這格只在「分組方式 = regex」時才會被讀取。
填的是正規表示式,不是檔名,而且必須含兩個具名群組:(?P<cam>…) 相機代號、 (?P<frame>…) 同一次曝光共用的編號。
例:檔名長 B-1_0-70924.jpg / N-1_0-61214.jpg,要抓中間的 1_0 當共用鍵 → ^(?P<cam>[A-Z])-(?P<frame>\d+_\d+)-\d+\.jpg$
rig 的基準鏡頭,其他鏡頭的外參都相對它表示, 所以要挑幾何最穩的那台(傾斜攝影就是正射那顆)。
留空 = 自動推薦,一般不用填。推薦邏輯:
‧ 有填「外方位參數 CSV」時 → 選檔名能對上 CSV ID 的那台。那顆就是廠商實測的頭, 也是唯一有資格把 ω/φ/κ 寫成重力先驗的頭 —— 這是不靠名稱的直接判定。
‧ 沒有 CSV 時 → 選曝光數最多的那台,並在 log 標明「這是弱猜測」,提醒你手動指定。
要手動填的話,填相機代號(資料夾名,或 regex 的 cam 群組值)。選擇結果都會印在 log。
只在 gps 模式生效:兩張影像的 EXIF GPS 距離小於此值就算同一次曝光。 同一機組同時曝光的座標通常完全相同,預設 0.5 m 已很寬鬆;航線間距遠大於此才不會誤併。 調太大會把相鄰站點併成一個 frame。
Camera
鏡頭畸變模型。預設 OPENCV(k1,k2,p1,p2)—— 比 SIMPLE_RADIAL 的單一參數更貼近真實鏡頭,測繪/航拍用這個。
兩個要注意的地方:
‧ BA 後端選 caspar 時必須改成 SIMPLE_RADIAL 或 PINHOLE,否則 Caspar 會跳過每一張影像、 完全不做 BA(面板會在開跑前警告,但不會阻止)。
‧ 自率定發散時,COLMAP 的 Mapper.max_extra_param(預設 1.0)會把任何畸變參數 絕對值 > 1 的相機判定為壞相機並靜默丟棄。正常鏡頭的 k1/k2 遠小於 1 所以不會踩到, 但**開了 rig 的話影響會放大** —— 一個 frame 裡只要有一顆鏡頭被判壞,整次曝光(全部鏡頭) 都會被一起退掉。registered images 數量異常少時,往這個方向查。
其他可用值:PINHOLE(無畸變)、SIMPLE_RADIAL、RADIAL、FULL_OPENCV(參數多、更容易自率定發散)。
per_folder = 每個 group 一台相機,共用內參。
抽 SIFT 前會把影像長邊縮到此值。 預設 auto —— 跟著下面「去畸變輸出」的 MAX_IMAGE_SIZE 走(沒設就取上限), 並且**永遠不超過 8192**。為什麼是 8192:COLMAP 送給 SiftGPU 的 -maxd 是 這個值 × 2(first_octave 預設 -1 的補償),所以 8192 已經等於 16384, 再往上大張航拍會 GPU OOM 直接 crash。
但不是越大越好。調小(例如 1920)會得到更粗、對大視角變化更穩健的特徵 —— 傾斜 rig 跨正射↔斜視的匹配常常反而更好。所以 auto 不是預設值: 要不要拉高是取捨,不是免費的。
填數值 = 釘死在該值。填 -1 = 交還給 COLMAP 自己決定 (那等同 3200 px,而且不會有任何提示 —— 注意 -1 不是「全解析」)。
判斷方式:如果你保留了高解析影像卻用 -1,姿態就是在 3200 px 上解出來的, 跟你留的解析度不相稱;但若匹配數本來就吃緊(斜鏡頭觀測少),就往下調而不是往上。 實際採用的數值每次都會印在 log。
default_focal_length_factor;留空 = COLMAP 預設。未知內參的大場景:給焦距一個初始猜測(影像寬 × 此係數)。h3dgs 用 0.5。已有可靠 EXIF 焦距時留空。
Matching
sequential = 連續幀重疊比對 + 迴圈偵測(loop detection),適合有序連拍 / 影片幀。
vocab = 用 vocab tree 找外觀相近的影像比對,適合無序 / 大量照片。
both = sequential + vocab(預設):連續性 + 外觀迴圈閉合,最穩。
spatial = 用 GPS 鄰近度限制比對候選,適合大場景空拍 / 掃街(需每張帶 EXIF GPS)。
custom = hierarchical-3D-Gaussians 的自訂配對:連續 + 二次方步距 + loop closure + GPS 鄰近,產生明確配對表後用 matches_importer 匯入。適合「有序、超大量、多相機 rig」的大場景(比對數遠少於 exhaustive)。建議搭配 MAPPER=hierarchical。
exhaustive = 每一對都比,不做檢索篩選。配對數是 n(n−1)/2(1000 張 ≈ 50 萬對),所以只適合幾千張以內。什麼時候非它不可:一批照片裡有兩群、群內相似度遠高於跨群相似度時(例如同一件物件先正擺拍一輪、再倒擺拍底面),vocab / sequential 的檢索名額會全部給同群鄰居,那少數幾對「把兩半縫起來」的跨群配對根本不會被嘗試 —— 只有 exhaustive 保證試過。
loop closure 只看「拍攝順序上相隔這麼多張以上」的影像。相鄰影像本來就被 SEQ_OVERLAP 的滑動視窗配過了,不排除掉的話會佔用 NUM_MATCHES 的候選額度,真正繞回同一地點的重訪反而擠不進來。0 = 不限制(COLMAP 預設)。注意視窗開了 quadratic_overlap(步距 1,2,4,…,2^(SEQ_OVERLAP-1)),實際覆蓋範圍遠大於 SEQ_OVERLAP,所以這個值要設得比 SEQ_OVERLAP 大才有意義。需要 COLMAP 4.3 以上。
每張比對的鄰近影像數。
單位公尺;依場景尺度調。
忽略高度,GPS 高程雜訊大時建議開。
二次方步距配對數/張;主力,預設 10。
連續鄰幀配對數/張;預設 0。
每張的 GPS 最近鄰數;0 = 不用 GPS,需 EXIF + exif 套件。
loop closure 視窗的 ±2^k 階數;預設 5。
手動 loop 錨點,成對整數 a b;每對代表第 a 幀≈第 b 幀。留空 = 不指定。配對名稱沿用 feature_extractor 的 image_list（每個 group 內依檔名排序),所以和資料庫一致。多相機 rig 請用「子資料夾 = 各相機」的 multi/nested layout。
較慢,低紋理多撿匹配;所有 matcher 通用。
Mapping
global = 全域式 mapper(預設):先 view_graph_calibrator,再一次解整張圖。
incremental = COLMAP 經典增量式 mapper,逐張加入重建。
pose_prior = 把 GPS 位置先驗放進 BA,大場景抗漂移、輸出直接是公制+地理對齊(需每張帶 GPS;此時不必再開下方 GPS 對齊)。
hierarchical = h3dgs 的 hierarchical_mapper:把場景切成重疊子模型,平行重建後合併,適合 global/incremental 撐不住的超大場景。輸出一樣落在 sparse/0,下游 train/undistort 不變。建議搭配 MATCHER=custom + 下方「大場景」的 simplify / 重力對齊。
位置先驗的不確定度(公尺)—— 它決定 BA 要多相信這些先驗。 預設 auto,依先驗來源自動決定:
‧ 有填「外方位參數 CSV」→ 0.05 / 0.05 / 0.10。廠商交付的 EO 是後處理過的航測 POS, 公分級精度;若沿用消費級 GPS 的公尺級數值,BA 會把它當雜訊、幾乎完全忽略, 等於白灌先驗。
‧ 只有 EXIF GPS → 3.0 / 3.0 / 5.0(消費級)。RTK 可手動填 ~0.02。
三格可以各自填數字覆蓋(例如只釘 Z),填數字就以數字為準。實際採用值會印在 log。
注意:這個值只有在位置先驗真的被讀取時才有意義 —— MAPPER 選 pose_prior 才會把位置放進 BA;選 global 時只會用到重力,位置先驗不參與。
外方位參數 CSV(選填,留空 = 不用):欄位 ID,EASTING,NORTHING,ELLIPSOID HEIGHT,OMEGA,PHI,KAPPA。ID 需等於影像檔名(不含副檔名);同一次曝光的其他鏡頭會用 EXIF GPS 自動配對。位置會覆蓋 EXIF 先驗;ω/φ/κ 只能以重力向量進 DB(COLMAP 沒有旋轉先驗欄位),要真正吃到完整姿態請走 point_triangulator。
EASTING/NORTHING 的投影;twd97_tm2_121 = EPSG:3826。
用 EXIF GPS 把 CSV 的站心配到同一次曝光的其他鏡頭。
僅檔名精確對到的影像。
global_mapper 旋轉平均時使用重力先驗。
視圖圖(view graph)斷成好幾塊時,COLMAP 4.3 預設會把每一塊各自重建成 sparse/0、sparse/1…(依註冊張數由大到小);在這之前只保留最大的那一塊,其餘影像整批丟掉。勾選 = 回到只重建最大元件的舊行為。不勾 = 用 COLMAP 預設(全部重建)。注意下游(undistort / 訓練 / 匯出)目前仍只吃 sparse/0,多出來的元件會列在 log 的「mapper produced N models」區塊供你判讀。
註冊張數少於這個值的模型直接丟棄,用來濾掉零星的小碎塊。留空 = COLMAP 預設(3)。需要 COLMAP 4.3 以上。
分區參數,留空 = 用 COLMAP 4.2 預設(leaf 500 / overlap 50 / workers -1 自動)。每個子模型最多影像數 / 相鄰子模型重疊影像數 / 平行重建子模型的 worker 數。
--Mapper.ba_use_gpu;大幅加速 BA,建議開。global_mapper 不吃這顆(它自己的 Ceres BA 預設就是 GPU)。
ceres = 預設;incremental/pose_prior/hierarchical 搭配上方 GPU BA 用 cuDSS,global 本身預設已是 GPU。caspar = COLMAP 的 SymForce GPU 解算器,接管 local+global BA(四種 mapper 都吃)。相機模型必須是 SIMPLE_RADIAL 或 PINHOLE,否則 Caspar 會跳過所有影像、不做 BA。incremental/pose_prior/hierarchical 選 caspar 時上方 GPU BA 勾選會被忽略。
座標與尺度（GPS 對齊 / 轉正）
這一組決定「重建出來的座標是什麼」。不確定就全部留預設 —— 預設是不動座標, 訓練與量測照樣能跑,只是尺度不是真實公尺。
什麼時候開:每張影像都有 EXIF GPS,而且你 Mapping 選的不是 pose_prior。 跑 model_aligner 把稀疏模型改寫成 ENU 真實公尺座標。
什麼時候不要開:① Mapping 已選 pose_prior(GPS 先驗已經進 BA,模型本來就是公制+地理對齊,再對一次是多餘的); ② 要用 Mesh 頁的 ChArUco mm 校正定尺度(兩者擇一,同開會打架);③ 沒有 per-frame GPS(影片轉幀就沒有)。
前提:GPS 需每張都有,非 100% 覆蓋會在開跑前中斷。
RANSAC 內點門檻(公尺)。只在上面勾了 GPS 對齊時生效。 消費級 GPS 3.0(預設);RTK 可降到 0.05~0.1 讓對齊更嚴格。訂太小會因內點不足而對齊失敗。
把場景轉成「up 朝上」,只改去畸變後的模型,影像不動。行為取決於上面的 GPS 對齊有沒有開:
‧ 有開 GPS 對齊 → 只做 Z-up→Y-up 軸轉,保留公制尺度。要「真實公尺 + viewer 正立」就兩個都勾。
‧ 沒開 GPS 對齊 → 用 PCA 猜重力方向轉正,並且會重新縮放場景(下面兩個參數才生效)。 ⚠ 如果你的模型已經是公制(例如 pose_prior 或事後自己對過),單獨勾這個會把公制尺度改掉。
縮放到「相機→點」中位距 = 此值(預設 20)。 只有在「勾了 auto_reorient 且沒開 GPS 對齊」時才生效,其餘情況這格填什麼都沒差。
手動縮放倍率;0 = 用上面的目標中位距自動算。同樣只在「auto_reorient 且沒開 GPS 對齊」時生效。
去畸變輸出（undistort）
這一組決定「交給 3DGS 訓練的影像長什麼樣」。
image_undistorter 的長邊上限。留空 = 不縮(建議) —— 去畸變不是瓶頸,原生解析度跑得動,砍在這裡等於直接丟掉 GSD。h3dgs 論文用 2048 是為了配合它自己的訓練預算, 你要原生解析度訓練就不要填。注意這跟上面 Inputs 的「影像解析度」是兩道獨立的關卡, 那一道已經先縮過一次了。
要做「只重建前景物件、去掉背景」時才填。填去背輸出的 no_bg/masks/(單通道那包;填 no_bg/cutout/ 會自動改用旁邊的 masks/)。會用同一組相機參數把遮罩一起去畸變(不然遮罩會對不上去畸變後的影像), 輸出到 <out>_*_mapper/masks,訓練時再搭配 LichtFeld 的「遮罩模式」。一般整場景重建留空。
預設關。關的時候遮罩只用在去畸變那一步, 背景照樣抽特徵、照樣參與解算 —— 整場景重建就該這樣。開了之後只有遮罩內的主體會約束解算, 這是單一物件重建才要的:例如同一件東西先正擺拍一輪、再倒擺拍底面, 物件被搬動過,房間跟物件之間就不是剛體關係,背景特徵只會給出錯誤的約束。 開這個要同時填 MASKS_DIR。另外遮罩和影像必須是同一個長邊, 所以上面的「影像解析度」要設成「保持原樣」(或用同一個長邊重跑去背)—— 對不上會直接報錯。
預設關。關的時候 <out>_*_mapper/images/ 是有背景的去畸變原圖,遮罩另外放在旁邊的 masks/ —— 吃遮罩的訓練器要的就是這樣。開了之後會拿那包遮罩 就地把 images/ 的背景塗黑,給只讀 images/ 的訓練器/檢視/Mesh 用。 會覆蓋原圖 —— 要拿回有背景的版本就 FORCE=1 重跑去畸變。 (JPEG 邊緣會有一點壓縮殘影,背景不是數學上的純黑;吃遮罩的訓練器不受影響。) 要同時填 MASKS_DIR。

融合(兩輪拍攝 → 一個 COLMAP)
一件物件立著拍,拍不到底面;翻過來再拍一輪就補得到。 這裡把兩輪合成 一個完整模型。
  1. 兩輪各自跑一次 ✂️ 影像去背,解析度要選同一個長邊(例如都 2560)。
  2. 下面各填一組去背產生的 no_bg 資料夾。
  3. 按 整理並檢查 —— 會告訴你每組幾張照片、幾張遮罩、對不對得上。
  4. 按 帶入 COLMAP 表單,參數照你原本的用法調,再送出。
為什麼一定要先去背?
因為物件在兩輪之間被搬動過。房間沒有動、物件動了, 所以房間跟物件之間不是剛體關係 —— 背景特徵會叫 COLMAP 去解一個不存在的幾何, 兩輪也就對不起來。把背景遮掉之後,整批照片只由物件本身的表面約束, 「正擺/ 倒擺」在數學上就不再是兩件事,而是同一個物件的 1000 多個視角。 這也是為什麼這裡收的是去背結果而不是照片資料夾。
填 no_bg 就夠 —— 照片是它的上一層、遮罩是它底下的 masks/,都會自動推出來(填上一層或 no_bg/masks 也認)。
fusion/ ├─ images/<每組> → 連到各組照片 ├─ masks/<每組> → 連到各組 no_bg/masks └─ colmap/ ← COLMAP 結果寫在這
都是 symlink,不複製檔案,原始資料夾不會被動到。
深度/法線生成
為每張照片產生深度圖和/或法線圖,輸出成 LichtFeld-Studio 格式的 depth/、normals/ 資料夾(同名同尺寸;PNG)。 訓練時加 --use-depth-loss / --use-normal-loss 會自動讀取。 兩種引擎寫出的編碼完全相同,下游不需要知道是哪一個產生的。
用 LichtFeld 自帶的 preprocess 指令(MoGe-2 ViT-B,模型第一次執行會自動下載,不需 conda/torch env)。
官方 PyTorch MoGe-3(Ruicheng/moge-3-vitl, 370M)。LichtFeld 沒有內建 MoGe-3 —— 它是把 MoGe-2 的架構手刻成 C++/CUDA, --model 只換權重不換架構,所以 MoGe-3 只能走這條獨立路徑。 在同一批空拍圖上,深度整體排序與 MoGe-2 一致(Spearman +0.995),但梯田邊界、 屋頂、電塔等細節明顯銳利許多;代價是每張約 0.5 秒(MoGe-2 約 40 毫秒)。

去背 / 前景遮罩(SAM)
  1. 選照片資料夾 —— 下面那格,或按「瀏覽」。
  2. 按「⬚ 匡選物體」 —— 照片會開在右邊,在要保留的東西上拖曳畫一個框。 只要框一張就好,資料夾裡其餘幾百張 SAM 會自己照著切,不用一張一張框。 (挑幾張各框一次會更準,但不是必要的。)這一步不能跳過 —— SAM 是靠這個框知道你要留什麼。
  3. 按「▶ 開始去背」 —— 整個資料夾一起跑,可以關掉頁面,工作在背景繼續。
它會產生什麼、放在哪裡
輸出兩包,都在你選的資料夾底下的 no_bg/ 裡: cutout/(去背後的 RGBA PNG,給人看)和 masks/ (0/255 單通道遮罩,COLMAP 和訓練器吃這包)。原始照片一個位元都不會動。 一張圖裡匡多個物體時,各自的遮罩會聯集成同一張 alpha,所以「一排並列的主體」 一次就全部保留。

facebook/sam3 在 HuggingFace 是需要申請的 gated repo: 要先到 huggingface.co/facebook/sam3 同意條款(人工審核), 核准後在這台機器跑一次 conda run -n sam hf auth login。 還沒核准就先用 SAM 2.1 —— 框提示的品質一樣好。
⚠ 追蹤傳播固定使用 SAM 2.1 影片模式,上面的模型選單在這個模式下不生效(選單會變灰)。 原因:SAM 3 的影片工作階段會把整段序列一次載進記憶體(每張放大到 1024²), 幾百張 4K 會吃光 RAM;SAM 2 的是從磁碟逐張讀。 想真的用 SAM 3 就選「範例提示」 —— 它每張獨立推論,不需要影片工作階段。
縮小後的複本存在 images_<長邊>/(跟 COLMAP 的縮圖選項同一套命名), 去背結果也在那個資料夾底下的 no_bg/ —— 之後要接 COLMAP/訓練,瀏覽時選這個子資料夾即可。 不同解析度各自存一份,不會互相覆蓋;原始照片不受影響。
兩包都寫在 no_bg/ 底下,不會散在照片旁邊。COLMAP 的 MASKS_DIR 和訓練器的 --masks 都吃 no_bg/masks/ (單通道那包);cutout/ 是給人看和給別的工具用的。
邊緣處理
去背的黑邊多半不是遮罩畫錯,而是邊緣那圈半透明像素的 RGB 其實是背景色。 先內縮再羽化,羽化的漸層就落在前景像素上,黑邊自然消失。
主體被切太瘦時才用(頭髮、電線這類細物)。
進階
顯存不夠時會自動減半重試;這裡是起始值。真正吃顯存的是「框的數量 × 整張解析度」的遮罩,不是編碼器。
COLMAP 的遮罩階段要求每張照片都有對應遮罩,所以預設是 opaque —— 缺檔會讓後面的 image_undistorter 直接失敗。
跑完覺得切得不好?先按上面的 🖼 檢視去背結果 看是哪幾張壞掉,點進去修 —— 整塊區域被漏掉時,先畫框再補點(框給「範圍」、點給「這裡也算主體」)。 實測同一張:只點 53 點 → 面積 0.30 但邊緣很雜;一個框 + 6 點 → 0.31 而且乾淨。 點很多下不會比較準。
分塊（大場景 → 每塊獨立訓練）
把重建好的場景切成子塊,每塊各自吃滿 splat 預算;要街道級細節用這個。
不用手算 —— 開該 job 的 3D 檢視器 → 底部工具列 ⬚ 選訓練範圍 → 框住要訓練的區域 → ▶ 用這個範圍去裁切/分塊,會自動帶回這張表單。
影像數不多（約 < 500 張）時通常只需要裁切範圍,不需要分塊 —— 這顆會設好 auto/rebalance 關、block_size 放大到只剩一格、buffer=0、切片關。
開啟時 block_size / buffer / max_images / min_images 全自動推導（目標每塊約 120 張）。要手動調再關掉它。
⚠️ 填了 region 又開自動分塊: 自動分塊會依全部相機數決定要切幾塊,region 內仍會被切成多塊。只想裁切範圍請按上面的 「✂️ 只裁切不分塊」。
手動模式:每塊相機數 ≤ max_images、≥ min_images,block_size 當最小塊邊。
切片 = 原圖裁成小張、主點跟著平移,訓練吃到原生 GSD。
